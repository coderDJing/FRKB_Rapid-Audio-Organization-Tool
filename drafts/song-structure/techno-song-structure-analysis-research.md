# Techno / EDM 段落算法历史研究档案

状态：历史研究记录，不代表当前生产算法

本文保存针对强压缩、低动态 Techno/EDM 的段落识别研究结论。历史版本号、旧指标和样本状态只用于追溯，不能作为当前算法能力或准确率依据。当前生产实现以源码为准（当前 Worker 使用 `buildSongStructureAnalysisV23`），样本、真值、prediction 和 benchmark 以[段落真值集与 Benchmark 工作流](./song-structure-truth-benchmark-workflow.md)为唯一入口。

## 1. 为什么传统方法会失效

- 总峰值在强压缩 Techno 中可能长期接近常量，不能单独承担段落边界识别。
- `attack` 若只来自总峰值包络上升，无法区分 kick、clap、synth、滤波或噪声层变化。
- 相对频带颜色表达频带占比，不能代替 absolute low/mid/high envelope；共同增减可能被抵消。
- 单 bar recurrence 会把共享底鼓的不同段落误认为重复；真正结构常在连续 4/8/16 bar 的趋势和纹理中。
- 先用固定段落模板同时决定边界和标签，会把没有传统 Drop 或有多个短 Breakdown 的歌曲强行套错。
- 降低全局阈值会同时放大 fill、crash 尾音、编码噪声和网格误差，不能替代曲内相对变化建模。

## 2. 可复用的设计原则

1. **边界与标签分开**：边界阶段只输出位置、显著度、证据来源和稳定性；标签阶段再决定 `kind` 与 `confidence`。
2. **特征与网格解耦**：基础音频特征不依赖 BPM、first beat、网格 signature 或标签权重；网格变化只重新投影 beat/bar，不重新解码 PCM。
3. **曲内相对变化优先**：保留少量 absolute 强度，同时使用 robust normalization、局部 4/8/16 bar 对比、进入/退出方向和多频带一致性。
4. **phrase 是软先验**：4/8/16 bar 对齐可用于候选加权和吸附，但不能禁止短过门、提前一拍或非标准长度。
5. **Drop 精度优先**：证据不足时宁可标 `groove`，允许歌曲没有 `drop`，不能用高能量本身制造播放范围误导。
6. **固定与动态网格统一投影**：动态 clip 边界是网格修正边界，不自动等于音乐结构边界；两类歌曲必须进入同一套结构语义链路。

## 3. 已排除的方向

- 按曲名、路径、固定时间或文件格式写特判。
- 使用全局固定 shift 修正边界或波形位置。
- 只靠单一起音阈值、单一频带或单个窗口决定结构。
- 用“段落超过半曲就硬切同标签”等模板补丁制造完整性。
- 在没有人工 truth 的开发样本上调参后，直接宣称准确率或泛化提升。

## 4. 重新开题前提

任何新的段落算法研究必须先：

- 从本机 truth manifest 确认样本、网格、split 和批准状态；
- 用正式 Worker 的同一解码后端运行 benchmark，并记录 `decoderBackend`；
- 先建立可复现的特征、边界和标签基线，再做单变量消融；
- 将 development 改善与 approved regression、holdout 证据分开；
- 通过用户试听后才更新 truth，不从旧 prediction 或聊天记录抄标签。

研究文档可以记录失败实验和架构取舍，但不再在这里维护当前版本号、逐曲数字、样本清单或操作命令。那些内容统一回到真值工作流和本机报告。
